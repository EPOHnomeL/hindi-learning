# Served Teach App Glossary

The domain language for an app that serves teach-skill lessons to the web and feeds learner interactions back to Claude Code. This glossary is the canonical vocabulary — explainers, issues, schema names, and code should adhere to it.

## Terms

**Lesson**:
A self-contained HTML artifact that teaches one tightly-scoped thing, generated by Claude Code's teach skill and served read-only on the web. The primary unit of the app.
_Avoid_: Page, article, module

**Hub (Neon)**:
The shared store for the *index and the conversation* — lesson/reference metadata (id, topic, order, R2 key, supersede status), Progress, Responses, Questions, Replies. Both Claude Code (via the Neon MCP) and the web worker read from and write to it. It is the asynchronous conversation between the learner and Claude Code. Artifact *blobs* live in the Artifact store, not here.
_Avoid_: Backend, database (when speaking about its role as the channel)

**Artifact store (R2)**:
The Cloudflare R2 bucket holding the rendered HTML blobs for Lessons and References. Written from the workspace files via `wrangler r2 object put`; served only through the worker's R2 binding (never a public bucket URL) so it stays behind the Cloudflare Access gate. The Hub holds the R2 key for each artifact.
_Avoid_: Bucket, file storage, S3 (in schema/user-facing language)

**Progress**:
The learner's relationship to a single Lesson: `unseen → opened → completed`. Cheap metadata, distinct from Responses, that lets the web show "you're here / next" and lets Claude Code spot a learner who opened a lesson but left no Responses (stuck). Not a heavyweight entity.
_Avoid_: Status (overloaded), completion, engagement

**Topic**:
One teaching workspace — a single subject the learner is studying (e.g. Hindi), owning one mission and a body of lessons. Maps one-to-one to a teach-skill workspace. A User may have many Topics ("teach me anything"); v1 has one.
_Avoid_: Course, subject, workspace (in user-facing language)

**Reference**:
A durable, compressed cheat-sheet (glossary, syntax, key facts) the learner returns to repeatedly. Unlike a Lesson it is mutable — Claude Code revises it in place as understanding deepens; the current version always wins. Captures nothing.
_Avoid_: Cheat-sheet, doc, note (in schema/user-facing language)

**Response**:
A learner's answer to something a lesson explicitly asked — a quiz selection or a free-text answer — always tied to a specific prompt within a lesson. Drives Claude Code's read on what has been mastered.
_Avoid_: Answer, submission, result

**Question**:
Something the learner raises unprompted while in a lesson ("I don't understand X"), tied to the lesson but not to any prompt. Has a lifecycle: `open → answered`. Forms an explicit to-do queue for Claude Code's next session — the asynchronous replacement for "ask the agent a follow-up."
_Avoid_: Comment, note, feedback

**Publish**:
The explicit action of pushing authored artifacts from the local teach workspace into the hub. Two paths, split by concern: the HTML blob goes to the Artifact store via `wrangler r2 object put` (file-based, no escaping); the metadata row (new Lesson, upserted Reference) goes to the Hub via the Neon MCP. A deliberate command, not a live sync. The local workspace remains the source of truth.
_Avoid_: Deploy, push, sync, upload

**Reply**:
Claude Code's answer to a specific Question, written back to the hub and readable on the web inline with the Question it answers. Transitions the Question to `answered`. The return leg that makes the loop a conversation rather than a feedback form.
_Avoid_: Response (that is the learner's, not Claude Code's), comment

**Routine**:
The unattended invocation of the teach loop (review → reply → author → publish) by Claude Code in the cloud, as opposed to a human-driven session. It is started two ways — a daily schedule and an on-demand fire from the reader — but only authors when the Frontier permits (see Frontier). v1 runs one Routine whose instructions fix it to the single Topic; advancing several Topics is a later concern.
_Avoid_: Job, cron, automation, agent (when naming the concept)

**Frontier**:
The highest-ordered, non-superseded Lesson in a Topic — the learner's leading edge. The Routine authors the next Lesson only once the learner has marked the Frontier `completed`, so a Topic holds at most one unread Lesson beyond what's done (a buffer of one). When the learner completes the Frontier, the reader offers to fire the Routine for the next one.
_Avoid_: Latest, head, tip, edge
