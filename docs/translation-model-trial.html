How each model fails — mechanically

Deterministic checks across all 9 languages, run through the real production guards. Every model cleared the hard quiz-scoring guard (markers + static blocks intact, 9/9) — so none would ship a broken quiz. The differences are in everything the guard doesn’t catch.

The three trends

1 · Scripture handling is the real dividing line
Gemini always fills in Bible verses — but sometimes invents or scrambles them (mangled references in Urdu, a coined “new covenant” inside a Hindi verse). Sonnet plays it safe and leaves verses in English for every harder language (zu, xh, hi-Latn, bn-Latn) — safe but incomplete for a scripture-based lesson. Opus threads it: real published wording where it’s confident (correct romanized Hindi John 3:16), English fallback only for Bengali. Best balance, and the rule the skill actually asks for.
2 · Gemini leaks native script into romanized editions
The mixed-script failure the fidelity rules explicitly warn about shows up only in Gemini: Devanagari bleeding into Romanized Hindi (“par परिस्थिति”), Bengali/Devanagari into Romanized Bengali. Sonnet and Opus kept every romanized edition in clean Latin script (0 leaks).
3 · Structural fidelity: Opus > Sonnet > Gemini
Opus preserved the HTML element count exactly in all 9 (0 dropped); Sonnet dropped a handful; Gemini quietly dropped 3–6 elements per lesson (23 total) and, in Afrikaans, fabricated whole steps that aren’t in the source. Recurring shared miss across all three: the fill-in quiz Q4 stem and the “Check” button often left in English.
